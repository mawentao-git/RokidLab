# HUD 主题创作规范（hud-design）

> 语法以 glass_hud 工具描述中的速查为准（解析器同源，写错会被拒并回传原因）。
> 本技能只管「怎么设计才不千篇一律」——契约、构图、动画编排、参考图工作流。
> 写完 scene 后按工具流程 preview → try → apply/save；省略 scene 即沿用上一次设计。

## 1. 创作契约（优先级高于一切语法：先立意，后落笔）

① 用户给风格词/意象时，先在内心回答三问——骨架是什么形状？它的「动」是呼吸、旋转、流动还是生长？它该住在屏幕哪里（一角/边缘/中心偏移）？然后选元素表达。忠于用户描述的意象，哪怕只给一个词；把屏幕当舞台不当海报：1 个视觉重心 + 低透明度氛围线做远景呼应，形成前中后三层深度；不对称比居中有张力；重复一个简单元素的耐心累积胜过堆砌多种元素。

② ⛔ 默认套路黑名单（用户未明确要求时禁止产出）：四角 brackets + 居中同心圆 + orbit 卫星点 + 底部 ruler 的组合（历史最高频套路，一眼假）；居中对称大圆环 + 中心 text 的「默认科幻脸」；照抄语法骨架里的 bg 数值——那只是形状示范。bg 按意象定制：扫描线/网格不是必需品，雨夜/故障=强 scanline，星空/数据空间=grid，干净极简=全 0 或干脆省略 bg。

③ 构图范式（每次生成先选一种；同一用户连续多次生成必须换范式）：居中对称 / 偏心放射 / 边缘框架 / 单向流动（横/纵/斜）/ 阵列重复 / 散落随机 / 纵排文字流 / 极简单线 / 角落栖息 / 满屏纹理。

④ 多样性铁律：连续生成与上一轮须在「构图范式、主体形状、运动类型」三个维度上至少两个不同——换风格词是换形状语言，不是换数值参数。**作用边界（2026-10-25 实测补）**：仅当用户要求**新主题/新设计**时生效；同一设计的 preview→try→apply/save 迭代不算连续生成，scene 必须原样沿用（工具不传 scene 即自动沿用），禁止为「求不同」而换构图。

⑤ 物理纪律（硬性）：官方表盘已有时间/日期/天气，禁止再做数据面板；单绿屏细线(0.5-1px)比粗线清晰，亮度分层不靠字号；元素宁少勿多；整屏动画节奏统一；主体元素群占屏面积≤40%，必须留呼吸区（除非用户明确要「全屏」）。

## 2. 正交构图示例（仅示范同一套 DSL 能长出多少种构图，禁止照抄；风格内容一律按用户意象自由发挥）

A 阵列重复·数字雨：{"v":1,"macros":{"rain":[{"type":"text","content":"7","x":"p.x","y":"expr:(t*p.v)%h","size":14,"opacity":"p.dim"}]},"scene":[{"type":"use","use":"rain","p":{"x":32,"v":90,"dim":0.7}},{"type":"use","use":"rain","p":{"x":96,"v":140,"dim":0.4}}]}
B 极简单线·波动：{"v":1,"bg":{"scanline":0.02},"scene":[{"type":"line","x":-180,"y":"expr:40*sin(t*0.8)","x2":180,"y2":"expr:40*sin(t*0.8+1.5708)","stroke":2},{"type":"dot","x":0,"y":"expr:40*sin(t*0.8+1.5708)","r":4,"anim":{"type":"glow","amp":0.4}}]}
C 角落栖息·数据：{"v":1,"scene":[{"type":"arc","zone":"B","x":-40,"y":30,"r":36,"start":90,"sweep":160,"stroke":1,"anim":{"type":"pulse","period":6}},{"type":"text","zone":"B","x":-40,"y":64,"content":"IDLE","size":10,"stroke":2,"align":"center","bind":{"key":"ai_state","as":"text"}}]}

## 3. 动画编排（用户要「多动画/丰富动效/热闹」时按此放开；用户没要求时仍守契约⑤的克制）

预算足够，别自发保守：整场景动画实例 <=48（组合动画每项算 1）、元素 <=128、JSON <=16000 字符——「很多动画」完全在预算内，不要自发砍到一两个，也不要因为怕超限而不敢用。

组合而非罗列：每个元素可带 1~2 个 anim 组合出复合动效——spin+glow（旋转+亮度呼吸）、orbit+pulse（公转+透明度）、scale+pulse（尺寸+透明度）、dashFlow+fall（蚂蚁线+下落）；同元素同类型不重复，字段见 glass_hud 语法速查的 anim 行。

编排三法：① 分组错峰——同组元素给不同 phase（0/90/180/270），波浪与脉冲有先后，整屏不同呼吸；② 类型混搭——旋转类（spin/orbit）、呼吸类（pulse/fade/glow/scale）、流动类（dashFlow/fall）至少各占一类，别整屏只有一种动；③ 宏实例化——一个宏 use 多次、各带不同 anim 与 p 参数，一份定义长出多个独立运动的实例（数字雨/粒子串的标准做法）。

与契约⑤的关系：⑤（少元素、统一节奏）是默认审美；用户明确要「丰富/多动画/热闹/动起来」时以用户要求为先，按上述预算放开——契约为默认审美服务，不覆盖用户的明确指令。

## 4. 参考图工作流（主动找参考，不等用户开口）

用户给了具体风格词（水墨/蒸汽波/魔法阵/故障艺术/赛博霓虹…）而你对这种风格的视觉语言没把握时，先 search_web 搜「<风格词> 设计参考」→ 对最相关的页面调 fetch_webpage（结果末尾会列出该页面的候选图片 URL）→ 挑一张最贴切的 URL 直接传给 hud_image 登记，再把 image 元素放进构图重心。要不要检索取决于你对答案有没有把握，不取决于用户提没提「搜一下」。

单绿屏注意：彩色参考图直接上屏需用户明确要求；只借构图/形状语言时不必登记，融入矢量设计即可。用户已在对话里发过参考图时优先用那张，不必再搜。

## 5. 设计流程与 scene 一致性（2026-10-25 实测失守后加强）

- 流程：先 action=preview 给用户看手机端预览（实时动画卡）→ 按反馈修改 scene 重新 preview → 满意后 action=try 推眼镜试戴 60 秒 → 用户认可后 action=apply 常驻或 action=save 存为命名主题。
- ⛔ scene 一致性（最高优先级纪律）：**对同一个设计做 try/apply/save 时禁止重新生成 scene**——不传 scene 即自动沿用上一次设计的 scene。用户说「预览/试戴/上屏/保存/就这个/可以」等动作词而没有要求修改设计时，一律不传 scene；只有用户明确说「改/换/调整/重新设计」时才传新 scene。用户要求修改时基于上一次的 scene 改字段，不推倒重来。
- ⚠️ 已发生过的真实事故：用户「设计一个水墨 HUD」（preview+scene）→「在眼镜预览」（模型当新创作重新生成了一版，还被契约④逼着换了构图，正好换进黑名单套路）。动作词 ≠ 创作请求，这是纪律不是建议。
